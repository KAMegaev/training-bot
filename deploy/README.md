# Подготовка сервера

Compose запускает PostgreSQL и Telegram-бота отдельными сервисами.
Проверено на Ubuntu 24.04 x86_64. Для первого пользователя достаточно 1 CPU / 2 ГБ RAM.
Модели работают через внешнее API. Приложение и база ограничены по памяти.

1. Передайте `bootstrap.sh` и публичный SSH-ключ на новый сервер.
2. От root запустите `bash bootstrap.sh /path/to/public-key.pub`.
   Скрипт устанавливает Docker из официального APT-репозитория, создаёт пользователя
   `trainer` и включает UFW. Открыты SSH, HTTP/HTTPS и существующая панель на 1500/1501.
   Существующие правила UFW сохраняются. Пароль root и текущий доступ не меняются. Docker-порты могут обходить UFW;
   поэтому у PostgreSQL намеренно отсутствует публикация портов.
3. Проверьте отдельное SSH-подключение как `trainer`. Доступ к Docker даёт пользователю
   административные возможности; ключ должен оставаться у владельца сервера.
4. От `trainer` скопируйте/клонируйте код в `/opt/training-bot` и выполните:

```sh
cd /opt/training-bot
python3 deploy/create_server_env.py
docker compose --env-file .env.server up -d --wait db
docker compose --env-file .env.server build tools
docker compose --env-file .env.server run --rm tools init
python3 deploy/configure_app_role.py
docker compose --env-file .env.server run --rm tools status
```

Пароли базы генерируются на сервере. Файл `.env.server` не включается в Git или Docker image.
`.env.bot` содержит настройки из `.env.example`, ключи Telegram/OpenAI и ID владельца,
но не пароль администратора базы. Заполняйте его локальным редактором или передавайте
через защищённое SSH-соединение. Права файла — 0600.
Роль `training_app` имеет права чтения/изменения таблиц и последовательностей;
она не может создавать роли, базы и таблицы. `tools init` выполняется администратором
перед новой версией. Скрипт настройки роли применяет права и к будущим таблицам.
Не запускайте `docker compose config` без `--quiet` в публичных логах: вывод содержит
подставленные секреты. Данные сохраняются в именованном Docker volume при перезапуске.
Не используйте `docker compose down -v`: это удалит базу.

## Запуск бота

После проверки ключей и импорта истории:

```sh
docker compose --env-file .env.server run --rm tools disconnect-webhook
docker compose --env-file .env.server up -d bot
docker compose --env-file .env.server logs --tail 20 bot
```

При обновлении: получить код, выполнить build, `tools init`, настройку роли и
`up -d --force-recreate bot`. Секреты не находятся в образе; база хранится в volume.
Логи приложения не содержат текстов пользовательских сообщений и значений ключей.
Проверьте `/id`, `/last`, вопрос о рекорде, черновик текстом/голосом и подтверждение.

## Резервные копии

`bash deploy/backup.sh` создаёт PostgreSQL custom dump в `backups/`, проверяет его
оглавление и хранит ежедневные копии 14 дней. Каталог закрыт правами 0700, файлы — 0600.
Для ежедневного запуска в crontab пользователя `trainer`:

```cron
30 3 * * * /bin/bash /opt/training-bot/deploy/backup.sh >> /opt/training-bot/backups/backup.log 2>&1
```

Копии на том же диске не заменяют внешнее хранилище. Перед эксплуатацией скачайте
копию на другой компьютер и проверьте её восстановление в отдельную временную базу.
Автоматическая доставка во внешнее хранилище требует настройки выбранного хранилища;
этот репозиторий не содержит его ключей или адресов.

Перезапуск Docker вместе с системой включён; контейнер базы имеет `restart: unless-stopped`.
Контейнер приложения также имеет `restart: unless-stopped`. Пока используется один
процесс polling с последовательной обработкой сообщений.
