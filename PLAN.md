# План запуска Telegram-бота тренировок

Обновлено: 23 октября 2026.

## Принятые решения

- Существующий Telegram-бот; новая программа вместо Albato.
- Сервер у FirstVDS, круглосуточная работа независимо от Mac.
- Python + aiogram; PostgreSQL хранит всю историю и выполняет запросы.
- OpenAI API: GPT-6 Luna — первый кандидат для разбора и работы с инструментами;
  выбор подтверждаем доступностью в аккаунте и проверкой на реальных сообщениях.
- Распознавание голосовых сообщений: gpt-transcribe, с предварительным преобразованием аудио.
- Google Sheets не участвуют в вычислениях. Экспорт из базы — отдельная функция.
- Сначала доступ владельцу; затем явно разрешённым пользователям с изоляцией данных.
- GitHub: публичный репозиторий только с кодом и документацией (решение владельца).

## Порядок работ

1. **GitHub.** Подключить публичный репозиторий `KAMegaev/training-bot` к локальной
   папку. Не загружать `.env`, Excel, базы, резервные копии и переписку. Первый push
   после проверки состава файлов. Результат: код хранится с историей изменений.
2. **FirstVDS.** Заказан KVM x86_64, Ubuntu 24.04 LTS, 1 vCPU, 2 ГБ RAM,
   40 ГБ NVMe, Амстердам. Установленная провайдером панель ispmanager пока сохранена.
   Проверить применимость выбранного API
   к аккаунту и региону использования до привязки приложения к провайдеру модели.
3. **Подготовить сервер.** SSH-ключ, отдельный пользователь для приложения, обновления,
   firewall, Docker Compose, автоперезапуск. PostgreSQL без публичного порта.
4. **Подключения.** Настроить Telegram token, OpenAI API key и Telegram ID владельца
   в локальном/серверном файле секретов. Проверить Telegram getMe и реальный небольшой
   запрос к выбранной модели. Не сохранять ключи в GitHub или текстовых логах.
5. **База и импорт.** Сверить актуальность Excel с ранее использовавшейся таблицей.
   Импортировать упражнения, синонимы, тренировки и подходы в PostgreSQL. Сохранить
   исходные строки и неопределённые сопоставления. Повторный импорт не создаёт дубликаты.
   Сверить число подходов, даты и контрольный рекорд жима.
6. **Работа бота.** Завершить запись текстом и голосом, подтверждение, исправления,
   отмену последнего действия, завершение тренировки, поиск и агрегаты по всей истории,
   экспорт, сохранение контекста и учёт токенов. Проверить разделение пользователей.
7. **Переключение.** После успешных проверок запустить приложение на сервере,
   отключить прежний webhook существующего бота и включить long polling. Проверить
   настоящими сообщениями запись, исправление, голос и аналитику. Повторная доставка
   Telegram не должна создавать подходы второй раз. Домен для long polling не нужен.
8. **Эксплуатация.** Ежедневные резервные копии PostgreSQL вне сервера и проверка
   восстановления, ротация логов, учёт расхода API. GitHub Actions запускает проверки;
   выпуск новой версии сначала явной командой с возможностью отката приложения.

## Текущее состояние

- Структура исходного Excel изучена; личные данные не публикуются.
- Созданы заготовки конфигурации, схем данных, импорта и функций журнала.
- Локальные зависимости установлены, `.env` создан из шаблона.
- Это незавершённая реализация: обработчик Telegram, интеграция модели и
  полноценные сквозные проверки ещё не завершены.
- Сервер подготовлен: доступ по SSH-ключу, пользователь trainer, Docker Compose,
  включён UFW с сохранением прежних правил панели. PostgreSQL запущен без публичного порта.
- Проверены сборка контейнера, создание схемы и чтение состояния PostgreSQL.
- Девять локальных тестов пройдены; исходный бот не переключён.
- Репозиторий GitHub подключён, публикация кода разрешена.
- В `.env` отсутствуют Telegram/OpenAI ключи и Telegram ID владельца;
  проверено только наличие значений. Секреты не выводились.

затем импортировать историю и закончить обработчик бота.
