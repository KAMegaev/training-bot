# Training Bot

Telegram-дневник тренировок с поиском и аналитикой по всей истории.

## Состояние проекта

Начальная версия слоя данных. Уже реализованы импорт Excel, справочник упражнений,
поиск подходов, рекорды, сводки, черновики записей и изоляция пользователей.
Telegram-обработчик, интеграция языковой модели, голос и серверное развёртывание
ещё в разработке. Команды ниже работают локально и не переключают Telegram-бота.

Планируемая архитектура: Telegram → Python / aiogram → PostgreSQL + OpenAI API.
Модель выбирает инструменты поиска; расчёты выполняются в программе и базе.

## Локальная подготовка

Требуется Python 3.11 или новее.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[test]'
cp .env.example .env
chmod 600 .env
```

Настройте `.env` при необходимости. Импорт и проверки не требуют API-ключей.
По умолчанию используется SQLite в `data/`; для сервера предусмотрен
`DATABASE_URL=postgresql+psycopg://USER:PASSWORD@HOST:5432/DATABASE`.

```sh
.venv/bin/training-bot init
.venv/bin/training-bot import-xlsx '/absolute/path/to/workbook.xlsx'
.venv/bin/training-bot status
.venv/bin/pytest -q
```

## Формат исходного Excel

Импорт ожидает листы «Справочник», «Синонимы», «Тренировки»:

- Справочник: код, универсальное название, английское название, группа мышц,
  вспомогательные мышцы, оборудование.
- Синонимы: исходное название, универсальное название, код, комментарий сопоставления.
- Тренировки: №, дата, зал, тренер, неделя, исходное название, универсальное название,
  вес, повторения, номер подхода, RPE, примечание, минуты, группа мышц, тоннаж,
  расчётный 1ПМ, исходная запись, подсказка названия, номер тренировки в программе.

Каждая строка — один подход. Файл читается без перезаписи. Пустые строки с заранее
вставленными формулами пропускаются. Повторный импорт того же файла не создаёт копии;
изменённая полная история требует отдельной сверки и не добавляется автоматически.
Идентификатор `owner` резервируется для владельца; он не привязывается к первому
написавшему боту пользователю.

Исторические тренировки группируются по дате, залу, тренеру и полям программы.
Несколько тренировок в один день с одинаковыми метаданными исходник не различает.
Любой комментарий в сопоставлении синонима консервативно помечает запись как
требующую проверки. Это не означает, что каждая такая запись ошибочна.

Тоннаж повторяет правило исходного формата: положительный записанный вес × повторения.
Вес одной гантели не удваивается. Нулевой, неизвестный и отрицательный вес различаются.
Расчётный 1ПМ вычисляется для 1–12 повторений; это отдельный показатель от реального веса.

## Конфиденциальные файлы

Репозиторий содержит только код и документацию. `.env`, Excel, базы данных,
выгрузки, резервные копии и ключи исключены через `.gitignore`.
Перед публикацией проверяйте `git diff --cached` и список `git ls-files`.
История диалога и тренировок хранится в базе, не в репозитории.

## Проверки и ограничения

Тесты используют синтетические данные и не обращаются к Telegram или OpenAI.
Проверяются поиск по истории, агрегаты, границы периода, изоляция пользователей,
повторное подтверждение записи, конфликт версий и отмена добавления.
Серверные проверки PostgreSQL и сквозные проверки Telegram/OpenAI предстоят
до запуска. Текущая заготовка не предназначена для эксплуатации без этих этапов.
