# Training Bot

Telegram-дневник тренировок с поиском и аналитикой по всей истории.

## Состояние проекта

Первая рабочая версия: импорт Excel, справочник упражнений, поиск подходов,
рекорды и сводки, запись текстом и голосом, подтверждение и исправления.
Данные каждого пользователя изолированы. Подготовлены Docker Compose,
PostgreSQL и резервное копирование. Запуск бота — отдельная команда.

Архитектура: Telegram → Python / aiogram → PostgreSQL + OpenAI API.
Модель выбирает инструменты поиска; расчёты выполняются в программе и базе.

## Локальная подготовка

Требуется Python 3.11 или новее.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[test]'
cp .env.example .env
chmod 600 .env
```

Настройте `.env` при необходимости. Импорт и проверки не требуют API-ключей.
По умолчанию используется SQLite в `data/`; для сервера предусмотрен
`DATABASE_URL=postgresql+psycopg://USER:PASSWORD@HOST:5432/DATABASE`.

```sh
.venv/bin/training-bot init
.venv/bin/training-bot import-xlsx '/absolute/path/to/workbook.xlsx'
.venv/bin/training-bot status
.venv/bin/pytest -q
```

Для локального запуска заполните `TELEGRAM_BOT_TOKEN`, `OPENAI_API_KEY` и
`OWNER_TELEGRAM_ID` в `.env`, затем выполните `.venv/bin/training-bot run`.
При неизвестном ID можно запустить с `OWNER_TELEGRAM_ID=0` и отправить `/id`:
в таком режиме доступ к истории закрыт всем. После настройки ID перезапустите процесс.
Если бот был подключён к другой программе через webhook, сначала выполните
`.venv/bin/training-bot disconnect-webhook`. Команда сохраняет ожидающие обновления.
Одновременно должен работать один процесс polling.

## Использование

Пришлите «Жим штанги лёжа 60 кг на 10, три подхода» текстом или голосом.
Бот подготовит черновик; подходы попадают в журнал только по кнопке «Сохранить».
Новая запись заменяет предыдущий неподтверждённый черновик. Черновики действуют сутки.
Для уточнения ещё не сохранённой записи напишите исправление отдельным сообщением.
Неоднозначное упражнение или недостающие повторения требуют уточнения.

Одна дата — одна тренировка пользователя; начинать и завершать её командами не нужно.
Явная дата в сообщении выбирает тренировку за эту дату. Следующие сообщения с
упражнениями без даты в тот же календарный день добавляются за последнюю выбранную
дату. Первая запись без даты в новый день относится к сегодняшней дате.
Например, 27 октября запись `01.10.2026: жим…` и следующая `тяга…` попадут за
1 октября; 28 октября первая запись без даты попадёт за 28 октября.
Выбор даты сохраняется в БД и переживает перезапуск; чтение истории его не меняет.
Граница дня определяется настройкой `TIMEZONE` (по умолчанию Europe/Moscow).

Правила короткой записи (инструкция ИИ в `training_bot/agent.py`, `SYSTEM`):

- `82.5х6 /5` — пять отдельных подходов по 82,5 кг × 6 повторений.
- `15х(10х2) /4` — четыре подхода по 15 кг × 10 повторений;
  к примечанию добавляется «на каждую руку/ногу», числа не удваиваются.
- Строка вида `х 6 х 5` без веса перед первым `х` пропускается.
  Явные 0, отрицательные веса и кардио по времени допустимы.
- Явно указанный зал имеет приоритет. Иначе «в Орёл/Орел/Орле» после даты
  означает ReZone; в остальных случаях — LikeGym. Зал виден в черновике.
- Дробь в скобках в строке даты, например `27.10.2026 (2/5)`, означает тренировку
  с тренером: для всех её подходов в столбце «Тренер» синхронизируется `да`.
  Отметка работает и вместе с залом, например `27.10.2026 (Орёл) (2/5)`.
- При выдаче истории каждый подход показывается отдельно, с сохранёнными
  значениями и примечаниями. Правила ввода не переписывают старую историю.

Можно отправлять одну тренировку целиком: дата, `Тренировка 2 (неделя 1)`,
нумерованные упражнения, строки плана и факта под каждым названием.
План `х6х5` пропускается; факт `20х6 /3` даёт три подхода, а не пять.
Поддерживается `20х6х3`, где последнее `х` заменяет `/`.
В подтягиваниях и брусьях `18х1` или `18 /1` — один подход на 18 повторений,
вес 0. `20х(7х3) /3` — три подхода по 21 повторению, вес 20 кг.
`Комплекс экстензия-пресс /3` сохраняется как три подхода одного упражнения
с пустыми весом и повторениями. Комплекс без числа подходов и упражнения
только с планом пропускаются. «(Орёл)» после даты означает ReZone.

Для этого формата числа разбирает `training_bot/notation.py`, а ИИ сопоставляет
названия со справочником через `search_exercises_batch`. `prepare_parsed_workout`
принимает только соответствия индексов и кодов: модель не может удвоить повторения
или заменить фактическое количество подходов плановым. Неизвестный формат
передаётся обычному диалогу без молчаливого удаления строк. Вариант через «или»
требует уточнения. Числа в названии (например, 21 и 45°) сохраняются.
В обычном диалоге `prepare_workout` принимает группы с `count`; программа
разворачивает их в отдельные строки до создания черновика.

Сообщение только с датой и строками вида `х 6 х 5` отклоняется программой без вызова ИИ.
Сопоставление и разговорный ввод проверяются отдельными тестами с реальным API:
`TRAINING_BOT_LIVE_EVAL=1 .venv/bin/pytest tests/test_notation_live.py -q`.
Они используют синтетические данные и временную SQLite, требуют `OPENAI_API_KEY`
в `.env`, расходуют API-токены и по умолчанию пропускаются.

Спросите «Какой мой максимальный вес в жиме за всё время?» или
«Покажи прошлую тренировку». Модель запрашивает нужные записи инструментами.
В запрос модели не передаётся весь файл тренировок. В контексте остаются последние
шесть пар реплик текущего календарного дня, текущий черновик и один последний подход;
вся история доступна в SQL. Дата следующей записи хранится отдельно от диалога.

- `/last` — последняя тренировка без обращения к ИИ.
- `/pending`, `/cancel` — показать или отменить черновик.
- `/undo` — отменить последнее сохранённое действие бота (импорт не удаляется).
- `/export` — CSV всей истории пользователя, `/usage` — расход за сегодня.
- `/table` — ссылка на Google-таблицу владельца, `/id`, `/help` — идентификатор и справка.

## Просмотр в Google Sheets

Одна Google-таблица с листами «Тренировки» и «Справочник упражнений» может служить копией истории владельца
для просмотра. Источник данных — PostgreSQL. После добавлений, исправлений и отмен
фоновая задача обновляет копию примерно в течение минуты. ИИ для этого не вызывается.
Другие пользователи и неподтверждённые черновики в копию не попадают.

Настройте `GOOGLE_SPREADSHEET_ID`, `GOOGLE_SHEET_TAB_ID` и путь
`GOOGLE_CREDENTIALS_FILE` к JSON-ключу служебного аккаунта. Google Sheets API должен
быть включён в проекте аккаунта; самой таблице нужен доступ редактора для его email.
Лист должен называться «Тренировки» и содержать ожидаемые 17 заголовков.
Столбец C «Упражнение как записано» содержит сохранённое исходное название,
рядом со стандартным названием в B. В новых записях модель сохраняет исходную
формулировку отдельно; при исправлении веса или повторов она сохраняется.
Для записей без сохранённой формулировки ячейка остаётся пустой.
Чтобы включить справочник, задайте `GOOGLE_EXERCISES_TAB_ID`. Ожидаемое имя листа —
«Справочник упражнений», заголовки: «Код упражнения», «Упражнение», «Группа мышц»,
«Оборудование». В него попадают все упражнения базы, включая пока не использованные.
Изменения справочника проверяются независимо от изменений тренировок.
Начальный файл и оформление создаются отдельно, затем синхронизация обновляет значения.
Без ID таблицы функция выключена. На сервере ключ монтируется отдельным файлом только для чтения.

Изменения сохраняются через бота. Значения в A:Q листа тренировок и A:D справочника принадлежат синхронизации:
ручные изменения будут заменены следующей выгрузкой. Фильтры и ширина столбцов
сохраняются. Не меняйте заголовки: при несовпадении синхронизация останавливается
для проверки. Повторный запрос после сетевой ошибки заменяет снимок целиком и не
добавляет копии строк. Удалённые отменой подходы исчезают из копии. При недоступности
Google бот продолжает сохранять в PostgreSQL и повторяет выгрузку позже.
Каждые шесть часов копия сверяется повторно даже при неизменной базе.

Разовое обновление: `training-bot sync-sheets --force`. Без ключа или доступа
автообновление не заработает; наличие ссылки само по себе не подтверждает подключение.

По умолчанию дневной лимит — 150 000 входных и выходных токенов на пользователя,
аудио — 30 минут в день и 5 минут на сообщение. Лимит токенов проверяется перед
каждым запросом и может быть превышен последним ответом. Это ограничитель приложения,
а не гарантированный финансовый лимит аккаунта OpenAI. Число шагов модели ограничено восемью.
Аудиофайлы хранятся только во временной папке до завершения обработки.

## Формат исходного Excel

Импорт ожидает листы «Справочник», «Синонимы», «Тренировки»:

- Справочник: код, универсальное название, английское название, группа мышц,
  вспомогательные мышцы, оборудование.
- Синонимы: исходное название, универсальное название, код, комментарий сопоставления.
- Тренировки: №, дата, зал, тренер, неделя, исходное название, универсальное название,
  вес, повторения, номер подхода, RPE, примечание, минуты, группа мышц, тоннаж,
  расчётный 1ПМ, исходная запись, подсказка названия, номер тренировки в программе.

Каждая строка — один подход. Файл читается без перезаписи. Пустые строки с заранее
вставленными формулами пропускаются. Повторный импорт того же файла не создаёт копии;
изменённая полная история требует отдельной сверки и не добавляется автоматически.
Идентификатор `owner` резервируется для владельца; он не привязывается к первому
написавшему боту пользователю.

Тренировки группируются по пользователю и дате; уникальный индекс не допускает
нескольких тренировок пользователя за один день. При обновлении прежней версии
выполните `training-bot migrate-calendar` после резервной копии: операция объединяет
дубли, сохраняет подходы и их удалённость, обновляет ссылки черновиков и сохраняет
предыдущее состояние в журнале операций. При конфликте метаданных операция откатывается.
Любой комментарий в сопоставлении синонима консервативно помечает запись как
требующую проверки. Это не означает, что каждая такая запись ошибочна.

Тоннаж повторяет правило исходного формата: положительный записанный вес × повторения.
Вес одной гантели не удваивается. Нулевой, неизвестный и отрицательный вес различаются.
Расчётный 1ПМ вычисляется для 1–12 повторений; это отдельный показатель от реального веса.

## Конфиденциальные файлы

Репозиторий содержит только код и документацию. `.env`, Excel, базы данных,
выгрузки, резервные копии и ключи исключены через `.gitignore`.
Перед публикацией проверяйте `git diff --cached` и список `git ls-files`.
История диалога и тренировок хранится в базе, не в репозитории.

## Проверки и ограничения

Автоматические тесты используют синтетические данные и не обращаются к Telegram
или OpenAI. Проверяются поиск, агрегаты, изоляция, повторная доставка сообщений,
подтверждение, конфликт версий, последовательная отмена исправлений, цикл инструментов,
лимит токенов и преобразование аудио. GitHub Actions запускает их при push/PR.
На сервере отдельно проверены операции PostgreSQL через ограниченную роль приложения
и реальные запросы к OpenAI. Распознавание конкретного голосового сообщения и удобство
диалога следует проверить в Telegram; качество распознавания и выбора инструментов
зависит от модели. Бот запрашивает подтверждение, чтобы можно было исправить ошибку.
